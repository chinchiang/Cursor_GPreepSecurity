# 流程與操作節奏

> 狀態：**暫存／待研究對齊**。CTEM 五階段是公開文獻中最穩定的骨架；與 3D、PEM、ASCA 的疊圖是本專案為了操作而做的對照，不是官方流程圖。

## 建議節奏（本專案工作流程）

```
範圍 Scope
  → 發現 Discover
    → 優先序 Prioritize（情報 + 業務脈絡 + 可利用性）
      → 驗證 Validate（AEV／AAE／控制評估，禁止真實 exploit）
        → 動員 Mobilize（修復、補償控制、Deny／Deceive／Disrupt）
          → 回到 Scope（攻擊面與業務範圍會變）
```

預測情報（PTI）不是第六階段，而是**灌入 Prioritize 與 Disrupt 的持續輸入**。ASCA 主要服務 Validate 與 Mobilize（控制是否真的開著、組態是否漂移）。

## 各階段要完成的事

### 1. Scope（定範圍）

- 輸入：業務服務地圖、資料分級、法規範圍、已知第三方。
- 動作：決定本週期要保護的「業務結果」而不是掃完整個 IP 段。
- 輸出：範圍聲明、資產／身份／資料物件的納入與排除理由。

### 2. Discover（發現）

- 輸入：範圍聲明、CMDB／EASM／CSPM／身份目錄、程式供應鏈清冊。
- 動作：列舉暴露（漏洞、錯誤組態、過期憑證、過度授權、暴露服務）。
- 輸出：去重後的暴露清單，每筆至少有資產、暴露類型、發現來源、時間。

### 3. Prioritize（排序）

- 輸入：暴露清單、威脅情報、業務關鍵度、攻擊路徑、現有補償控制。
- 動作：依**可利用性、可達性、業務衝擊、情報活躍度、修復成本**排序，而不是只看 CVSS。
- 輸出：本週期必做／可延／需驗證的分堆。**本站示範權重是專案設計，不是 Gartner 公式。**

### 4. Validate（驗證）

- 輸入：高優先暴露、控制組態、允許的驗證政策。
- 動作：用安全仿真、控制評估、攻擊路徑驗證確認「這筆是否真的開著」。禁止編寫或執行真實 exploit。
- 輸出：已驗證／無法驗證／偽陽性、證據摘要、殘餘風險。

### 5. Mobilize（動員）

- 輸入：已驗證暴露、負責人、變更窗口、自動化權限邊界。
- 動作：修復、補償控制、欺騙部署、移動目標、阻斷攻擊基礎建設。
- 輸出：工單與自動化工單結果、控制變更、3D 動作紀錄、未完成項。

## 和傳統弱掃週期的差別

| 項目 | 傳統弱掃 | 本專案對 CTEM／先制的理解 |
| --- | --- | --- |
| 頻率 | 季或月 | 持續，範圍滾動 |
| 排序 | CVSS 為主 | 可利用性 + 業務 + 情報 |
| 驗證 | 少，或年度滲透 | 高優先項要驗證 |
| 收尾 | 出報告 | 要有動員與回測 |
| 自動化 | 掃描本身 | 發現到處置的銜接 |

## 人工仍必須留下的決策

即使強調自動化，下列決策不應交給未監督模型：

- 對生產環境的破壞性驗證
- 對外攻擊或掃描第三方
- 把示範分數當成合規通過
- 更改雲端核准、生產防火牆或身份政策（除非已有書面變更流程）
