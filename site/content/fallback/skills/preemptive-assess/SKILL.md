# 先制型資安現況評估

你在協助使用者做**先制型資安（Preemptive Cybersecurity）現況快照**。先讀本檔，再決定是否需要 CTEM 或 3D 其他技能。

## 何時使用

- 使用者問「我們算不算先制」「該從哪裡開始」
- 要把 Detect and Respond 現況對到 CTEM 五階段
- 需要一份可給主管看的缺口清單，而不是掃描器原始輸出

## 硬限制

- 評分與紅綠燈若你自己加權，必須寫「**本專案示範設計，非 Gartner 官方規則**」。
- 禁止撰寫真實 exploit、惡意程式或攻擊 PoC。
- 禁止把缺少告警當成「已通過」。
- 禁止要求使用者把 API 金鑰貼進前端或此技能的範例。
- 來源不足時標「待驗證」，不要補假引用。

## 必要輸入

向使用者收集（缺項就列假設，不要默默填假公司資料）：

1. 要保護的業務結果（例如「支付清算不可中斷」）
2. 目前工具：EASM／VM／CSPM／SIEM／EDR／身份／欺騙
3. 暴露管理節奏：連續、每月、每季、無
4. 高優先暴露是否有**驗證**（仿真／控制評估／人工）
5. 修復或補償控制是否能在政策內自動或半自動進行
6. 是否已部署欺騙或移動目標
7. 合規或資料駐留限制

## 流程

1. **定範圍**：用業務結果縮範圍，不要一開始掃全世界。
2. **判姿勢**：反應／主動／預測／先制。先制需要「預測或驗證之後有政策內動作」。
3. **對 CTEM**：Scope、Discover、Prioritize、Validate、Mobilize 各寫現況、證據、缺口。
4. **對 3D**：Deny／Deceive／Disrupt 各寫有／無／部分，並註來源。
5. **輸出下一步**：最多五項，每項要有負責人角色、依賴、30 日可驗證結果。

## 品質檢查

- 每個缺口都對到階段或 3D，不要只寫「要加强資安」。
- 工具名稱與使用者提供的一致。
- 沒有證據的句子標假設。
